## 首轮合同收敛

这些是相对评审建议的显式缩小，不是静默模拟支持：

| 范围 | M0 决定 | 后续门禁 |
|---|---|---|
| Rule IR 金额 | 暂不开放 Decimal，拒绝而非浮点回退 | Flowable 精度探针及单位/币种合同 |
| 版本选择 | 只开放显式 PINNED | 业务日期路由、撤回/回滚规范单独验证 |
| 原料 | 仅 UTF-8 文本及真实行定位 | PDF/Word 解析、页码/表格定位探针 |
| 解释器 | 仅有界参考语义 | IR→DMN、反解析、固定定义 ID、一致性测试 |
| 例外 | 声明校验＋覆盖台账＋受权审批 | 真实抽取遗漏检测及独立业务金标 |
| 权限 | 宿主认证后接口＋合成主体测试 | 实际 IAM / 网关及真实账号隔离 |
| 生产 | 显式库调用，不启动工作流 | 受控组件任务、失败取消与重加工 |
| 发布 | 本地不可变快照与 CAS | 分布式部署原子性、撤回和运维恢复 |

原评审提出的 60 条工程用例保持为后续验收清单。当前只冻结并执行其中适用于 M0 的规则断言以及新增状态回归，不能用测试总数替代覆盖范围。30 条检索题尚未创建、冻结或执行；在真实解析/检索调优之前必须先固定来源、题目、金标、模型及组件版本。

## 下一阶段，保持四段顺序

### M0 收口

评审本仓库合同与剩余限制；不得据此发布真实银行服务。当前仅支持演示分类和参考执行模式，已显式阻断不支持的类型与版本策略。覆盖台账的人工确认仍是业务职责，不是编译器自动证明。

### M1 组件兼容性探针

1. 先固定 RAGFlow/Docling 的版本和同一组授权中文制度，测试条款、表格、空行及异常格式定位；保留解析失败，不把原文回退冒充解析成功。
2. Flowable 以评审定位的 8.0.0 作为待验证候选，不假定最新即兼容；确认实际 JUEL/DMN 子集、周年边界、布尔及整数类型、UNIQUE 命中、固定定义 ID、XML 外部实体禁用。
3. 只有 probe 通过才实现受控 IR→DMN 编译。以冻结金标逐条比较参考语义和真实引擎；金额需独立精度探针，未通过继续拒绝。
4. 真实抽取必须覆盖同句例外与来源范围，输出候选，不由模型自行审批。FAQ 独立使用文档产线，增加真实检索质量门禁。

不在本轮下载并启动全套开源系统，不提前假定组件 API 相容。

### M2 发布与变更闭环

接入持久生产任务、失败/取消、权威来源事件、全产品重建和原子服务切换。首期不做细粒度语义增量编译。Source Watcher 仅登记变化及受影响对象，不自行授予来源效力。未确认变化不阻断旧正式服务；确认生效且新知识未就绪时，按范围阻断旧判断。

### M3 Harness 最小接入

新增标准 Knowledge QUERY 合同与一个受管 Provider，两种产品使用同一适配器；按固定连接、产品、Manifest、当前身份与用途调用。安装 Lock 与知识快照、回执及运行 trace 对齐。复用现有授权和 Runtime 接线，不改通用授权语义、不新增 Agent 平台、不扩 TASK。

## 公共内核的规模边界

Core 只掌握版本化对象、引用闭包、状态门禁和证据关联。Schema 目录是合同维护源的导出；SQLite 是隔离 POC 存储，不替代企业 IAM、对象存储、任务调度、规则引擎和审计平台。任何外部组件接入失败，都不能通过回退到此参考解释器伪造真实组件成功。
