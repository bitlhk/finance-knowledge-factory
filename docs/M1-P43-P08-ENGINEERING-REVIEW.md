## 发现与最小整改

### P0 执行资格不能由模型声明决定

`coverage.py:57` 起的检查只能证明 EXECUTABLE 有合法结构，`coverage.py:119` 起的投影会复制模型谓词。它们不能证明谓词符合原文。

P43-2 把同意展期转成 `extension_months == 0`，把一半上限转成 `extension_months <= 0`。P43-1 还有短期限分支使用 `<12` 的边界错误。这些是确定的语义错误，不是表达差异。

旧独立评测拒绝了这些候选，没有证据表明错误规则正式发布。但仅靠冻结金标无法保护未来未见条款。最小整改是新建 M1 转换门禁：语义识别与公式生成分离，公式只由受控模板及已校验操作数生成。原文不支持的数值、授权前提和算术不得进入可执行产物。不要用条款 ID 分支或金标答案生成规则。

### P1 金标遗漏了原文触发条件

`coverage_gold.py:22-40` 没有表达借款人申请展期这一触发条件。P43-2 的 `clause-43-1` 实际保留了它，却被旧评测记为 `UNASSESSED_UNITS`。

复现：读取 P43-2 最后一条 assessment.checks；对照原文第一句和 GOLD.P43.units 即可。这个诊断不等于模型多编了事实。

最小整改：新版覆盖表补触发条件及其适用关系。旧评测保留；新增内容是否正确应看原文，不应以超出金标集合一律认定业务错误。

### P1 一般规则与有条件延长没有完整的机器可判分支

`coverage_gold.py:46-56` 中 business 与 ceiling 的 appliesWhen 都只有 `purpose_kind == BUSINESS`，另用 `alternative_to` 连接。该边只能表达存在替代关系，不能证明两条适用条件互斥，也不能给出例外资格。

一般五年与满足条件时适当延长，不等于两个可以随意选择的数值上限。不得用 `any(months<=60, months<=120)` 替代，更不能把后者推广到全部经营贷款。

最小整改：在语义层保留默认约束、限定例外及例外确认状态；尚未核验例外时继续阻断相关判断。不要为放行扩展 M0 或删除 unresolved。孤立的数值比较最多说明该数值子条件，不能作为期限合规结论。

### P1 严格结构评分混入了表达差异

`coverage.py:79-109` 要求匹配固定 kind/state、单元拆分及边集合。P08-2 的现金流资格与允许延长共用一个原文单元，仍保留 BUSINESS 范围以及十年上限的 requires 关系。不能仅凭合并就断言条件丢失；也不能因此直接改为 PASS。

P12 把其他贷款人条件保留为 MANUAL，金标要求 EXTERNAL。这主要是分类及依赖表达差异；外部要求具体内容仍未知，不能认定已经核验。原文引用完整不等于依赖已解析。

最小整改：新版附加复核将“语义错误”“表达差异待核对”“依据不足无法验证”分开。允许多个检查点追溯同一原文片段，但必须分别验证对象、模态、条件归属和依赖。分类标签相近不自动豁免关系检查。

### P1 相同待复核结果不能验证分支正确

`coverage_gold.py:57` 为 P08 三个子条件复用旧的四条 REVIEW_REQUIRED 用例。`tests/test_m1_clause_coverage.py:test_same_review_outcomes_do_not_hide_misbound_cashflow` 已证明：错误绑定现金流后，结果仍可全部待复核。

最小整改：保持旧 24/30 统计不变；新增语义关系断言与数值子条件断言，分别验收。不是放宽 REVIEW_REQUIRED，也不是通过增加类似状态用例证明抽取质量。

## P43 可确认判定表

以下是该固定原文的工程解释，不代表整条业务审批被自动化。

| 检查点 | 工程判定 | 自动化边界 |
| --- | --- | --- |
| 触发条件 | 借款人申请展期时进入相应评估流程 | 不能从任何月份值推断申请已提出 |
| 审慎评估与同意 | 评估原因、还款安排；是否同意须有业务流程证据 | 不能用数值比较证明已经同意 |
| 合理确定期限 | 需结合还款来源等实际信息 | 满足上限不等于期限已合理确定 |
| 短期限分支 | 原期限不超过一年时，累计展期期限不超过原期限 | 固定完整月输入域内：O<=12，E<=O；12 的边界必须覆盖 |
| 长期限分支 | 原期限超过一年时，累计展期期限不超过原期限的一半 | 当前 IR 不支持该运算，UNSUPPORTED；不能用零或原期限代替 |
| 后续管理与分类 | 两项义务均须保留 | 不从 E<=O 推导它们已经完成；不是模型决定风险分类 |
| 最终结论 | 数值子条件满足不等于允许展期或整条合规 | wholeClauseDecision 保持 NOT_EVALUATED |

完整月是工程 POC 的输入约定，不是原文定义的通用日期换算规则。含零头日、非整月、周年边界的合同期限未被当前词表充分覆盖，不应截断成整数月后放行。必须由可信上游确认度量口径，否则待确认。

P43-2 的 followed_by 还存在方向问题：合理期限单元指向同意单元、后续管理单元指向合理期限单元。按当前 from 后接 to 的定义，这与文本表达的条件和后续义务顺序不符。但后续管理和风险分类不应被强制解释为必须串行完成的两个工作流步骤。
